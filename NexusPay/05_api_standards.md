# Стандарты проектирования REST и gRPC API

**Версия документа:** 2.2  
**Владелец:** Архитектурный комитет  
**Связанные документы:** `04_system_architecture.md`

## 1. Общие правила REST API (External)
Внешнее API для мерчантов следует стандарту **OpenAPI 3.1**.
* Базовый URL: `https://nexuspay.ru`
* Формат данных: строго `application/json` в кодировке UTF-8.
* Именование полей: `snake_case` (например, `merchant_id`, `created_at`).
* Дата и время: строго формат **ISO 8601** в часовом поясе UTC (`2026-11-24T12:00:00Z`).

## 2. Идемпотентность
Все изменяющие запросы (`POST`, `PATCH`) на создание платежей и возвратов обязаны содержать заголовок `Idempotency-Key` (формат UUID v4). Ключ кэшируется в Redis на **24 часа**. При повторном запросе с тем же ключом сервер возвращает исходный HTTP-статус и тело ответа без повторного списания средств.

## 3. Формат ошибок
При возникновении ошибки API возвращает стандартную структуру RFC 9457 (Problem Details):
```json
{
  "type": "https://nexuspay.ru",
  "title": "Недостаточно средств",
  "status": 422,
  "detail": "На балансе мерчанта недостаточно средств для проведения возврата.",
  "trace_id": "9f8e7d6c5b4a3f2e1d"
}
```

## 4. Пагинация
Для списочных методов используется **cursor-based pagination** (параметры `cursor` и `limit`, максимальное значение `limit` — **100**). Использование `offset/limit` запрещено из-за деградации производительности на больших объемах транзакций.
