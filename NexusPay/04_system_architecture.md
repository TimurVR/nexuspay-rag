# Архитектура платформы NexusCore

**Версия документа:** 4.0  
**Владелец:** Архитектурный комитет  
**Связанные документы:** `01_company_overview.md`, `05_api_standards.md`

## 1. Высокоуровневый обзор
Платформа построена на базе **событийно-ориентированной микросервисной архитектуры** (Event-Driven Architecture). Все сервисы развернуты в Kubernetes (Managed K8s) в двух геораспределенных зонах доступности: `ru-central1-a` и `ru-central1-b`.

## 2. Основные микросервисы
* **`api-gateway` (Envoy + Go):** точка входа, терминирование TLS, rate-limiting и проверка JWT-токенов мерчантов.
* **`payment-orchestrator` (Go):** конечный автомат (Saga orchestrator), управляющий жизненным циклом платежа.
* **`fraud-checker` (Python / FastAPI):** синхронный вызов ML-моделей `ShieldGuard`. SLA ответа — не более **45 мс**.
* **`ledger-service` (Go + PostgreSQL):** сервис двойной записи (double-entry bookkeeping), отвечающий за консистентность балансов.
* **`webhook-dispatcher` (Go + Kafka):** гарантированная доставка уведомлений о статусах платежей во внешние системы мерчантов.

## 3. Взаимодействие сервисов
1. **Синхронное:** по протоколу **gRPC** (Protobuf v3) для критического пути проведения платежа (`api-gateway` -> `payment-orchestrator` -> `fraud-checker`).
2. **Асинхронное:** через брокер сообщений **Apache Kafka** (топики `payments.events.v1`, `billing.invoices.v1`) для аналитики, нотификаций и пересчета балансов.

## 4. Отказоустойчивость
При недоступности `fraud-checker` более 2 секунд срабатывает паттерн **Circuit Breaker**: платежи на сумму до **5 000 рублей** пропускаются по упрощенным правилам (fail-open), платежи свыше этой суммы отклоняются с кодом `503_RISK_UNAVAILABLE` (fail-closed).
